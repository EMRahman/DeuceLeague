DeuceLeague
For coaches

A straightforward league for players and coaches.

A club member built this for our club. Players report scores and check the tables on their phones. You run the league with Claude Code. The code is open source, so the club controls the experience and nobody can fill it with unwanted adverts or upgrade offers later.

Why it exists

The app we use now makes its money from us. Its screens fill up with adverts and upgrade offers, and each new version adds more of them. A club league doesn’t need that. It needs somewhere to report a score, a table and a list of who still has to play.

DeuceLeague has no business model. The club runs its own copy on a small server for about the price of a can of balls a month. Nobody sits between you and your players, and every player’s details stay in the club’s own database. Optional club notices or sponsor acknowledgements can be added later if you want them; they are not part of the basic player journey.

No unwanted advertsYou decide whether any club or sponsor message appears. League tasks stay first.
No passwordsPlayers sign in once from an email link and stay signed in on that phone.
No app to installIt’s a website that works on any phone, and players can add it to their home screen.
The club owns itThe club keeps its own server, its own data and its own backups.

What players see

A player opens the site a few times a month to do one of four things: agree a score, report one, see where they stand, or see who they still have to play. Each of these is a tap or two from the home page.

These are the real pages, filled with made-up results. Links and buttons don’t work in this preview. Scroll inside each phone to see the whole page.

A score counts only when both sides agree

Either both players report the same score, or one accepts the other’s. Nothing is confirmed just because time has passed. If the two scores differ, the site shows each player exactly what differs so they can sort it out. If they can’t, you decide.

What you do: ask Claude Code

For the first season, you tell Claude Code what you want in plain English. It reads the league’s published instructions for its API, shows you the important names, dates and division changes, and makes the changes. You stay in charge. The software suggests promotions and relegations, but it never makes them. It closes reporting at the season’s deadline, but it never decides a score. You know things the data doesn’t, such as who was injured, who’s moving away, or who ought to be in a higher division.

Setting it up

The league runs on a small rented server that the club controls. Claude Code runs every command from the setup guide, docs/SELF-HOSTING.md. A few decisions are yours, and so are the accounts. We’ll do the first setup together. It takes about an hour, most of it waiting for the new web address to start working.

  1. Rent a server and turn on its backups youA Hetzner Cloud account and their smallest server. You pay for it, so the club owns it.
  2. Choose the address youFor example league.yourclub.org. You add one DNS record to the club’s domain, or we buy a new domain.
  3. Choose an email service youThis sends players their sign-in links. It could be Postmark, Amazon SES, or a Gmail account with an app password. You add two DNS records so the emails don’t land in spam.
  4. Install and start everything Claude CodeIt installs Docker, sets up the database, the league and the website, and turns on HTTPS. It checks each step as it goes.
  5. Create the club Claude CodeThis prints the club’s master key once. You keep that key in a password manager. Claude Code gets keys of its own that can only do their particular jobs.
  6. Add members and the first season Claude CodeMembers come from a spreadsheet of names and email addresses, and divisions from our last tables.
  7. Sign in on your phone youThen send the link to the players.

Looking after it

The database is copied every night, and the last fourteen copies are kept. The server provider also backs up the whole machine. Upgrading means pulling the new version and restarting, and the database updates itself on the way. Once a season, restore a backup onto a spare computer to check the backups actually work. Claude Code can do this with you.

How it’s built, and how it can grow

There are two layers. A small core holds the league data and rules. Around it sit the pieces players actually use, and those can be changed, replaced or added to without touching the core.

The core open source · AGPL

  • Members, seasons, competitions, divisions and matches, in 13 tables
  • Scoring rules, tiebreaks and promotion places, stored as settings
  • Tables worked out fresh from the results each time, never stored
  • An API that every screen and bot talks to

Anyone can improve the core. If someone changes it and runs it for others, they have to share their changes, so it can never be turned back into a closed, ad-funded product.

Around it yours · MIT

  • The player website (built)
  • Optional club notices, only if you ask for them
  • A Telegram group bot
  • A table on the club’s own website
  • Anything else someone wants to build

These pieces talk to the core the way any app would. You can keep them private and brand them however you like.

Ideas someone could build with Claude Code

Telegram bot

Posts each agreed result and weekly table changes to the club group. It could also take scores (“6-3 6-4 v Alex”), once it has checked it’s really the player writing.

Nudges before the deadline

Drafts a message to everyone with matches outstanding, a month out and again a fortnight out. You approve each one before it goes.

Tables on the club site

A small box on the club’s existing website showing the current divisions.

Several clubs, one league

The core can already hold many clubs, each kept completely separate, so a county association could run leagues for all its clubs on one server.

Built to be trusted

  • Players’ personal details are protected. Players only see each other’s display names. Emails, phone numbers and dates of birth need a special permission that the coach controls.
  • If someone asks to be erased, their personal details are removed and their results stay, as data protection law (GDPR) requires.
  • Every change is logged, including who made it and when, and nothing in the log can be quietly edited afterwards.
  • About 200 automated checks run before any change is accepted, most of them against a real database, so the rules above hold.
